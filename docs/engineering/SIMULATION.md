# Deterministic simulation specification

Initial tuning is in [ECONOMY](../design/ECONOMY.md). This document owns update and physical rules.

## Time and work scheduling

Fixed 20 Hz. A tick always advances 0.05 simulated seconds. Render accumulation adds clamped wall delta multiplied by selected speed. Limit app catch-up to 8 ticks/frame; retain at most 0.5 real seconds of backlog then discard excess wall time and report “Simulation limited” in diagnostics. Never silently enlarge dt. A long OS sleep pauses/resets the accumulator; it does not simulate an absence.

Gameplay never reads the system clock. Headless simulation advances an explicit number of ticks without rendering. Input commands execute at tick boundaries ordered by monotonically assigned sequence; while paused they may execute at the current boundary, without advancing biology.

Tick order is a contract:

1. Apply queued valid commands (app/game boundary); update effective run parameters.
2. Refill food sources on due ticks; rebuild invalid navigation data before use.
3. Recompute colony needs once per second; reconsider eligible tasks every 10 ticks, staggered by stable ID modulo 10.
4. Sense targets, acquire reservations in stable-ID order, and request budgeted paths.
5. Move actors; enforce solid-cell/bounds constraints; resolve arrivals in stable-ID order.
6. Complete pickups, deliveries, dig hits, and nursing visits. Emit typed events for completed physical work.
7. On second boundaries, consume nutrition, accrue care/progress, lay eggs, and age/starve entities.
8. Resolve death before maturation; apply queued destruction/spawns sorted by stable ID; update phase and lifetime statistics.
9. Every 4 ticks, evaporate/diffuse pheromones; deposit pending successful-return trail values.
10. Game consumes work events exactly once, refreshes derived availability, checks invariants in debug builds, increments tick.

No entity is destroyed while iterating a registry view. IDs and event order remain stable after save/load. A brood that starves on a maturation boundary dies rather than producing a worker first.

## Reproducibility

Use a documented portable PRNG (PCG32 with stored state/increment and reference vectors) with separate terrain, behavior, and life-cycle streams. Rendering owns an unrelated visual stream. Do not use `random_device` inside sim, `std::uniform_real_distribution`, unordered-container iteration, or EnTT storage order for authoritative decisions.

A new seed is generated by app once and stored. Systems requiring stochastic decisions iterate actors sorted by stable ID; other systems may use stable packed arrays if order independence is demonstrated. On load rebuild sorted IDs before ticking. Store all mutable random stream state. Counter-based hash noise is suitable for terrain textures.

Guarantee first: same build + content snapshot + seed + ordered commands produce the same canonical state hash. Cross-platform exact equality is a target only after fixed-point math and tests establish it; do not advertise bit-exact portability prematurely. Canonical hashes exclude UI and recomputable caches, include pheromones, timers, reservations, RNG, cargo, and counters.

## World and topology

Initial world: 384x216 cells, 32x32 chunks, top 32 rows surface/sky. Four-neighbor movement; roots/bedrock impassable, soil and clay diggable. No diagonal corner cutting. Seeded layer variations must preserve a starter entrance, chamber, surface route, and two reachable sources.

Air cells have semantic regions (surface/nest); reachable nest air determines nursery capacity. All ants share navigable cells without collision solving. Avoid overlap visually with deterministic small offsets; these never change physical passability.

Movement is integer subcell distance per tick with residual carry so fractions are not lost. Worker speed starts at 6 cells/sec. An arrival cannot overshoot a solid tile. Paths comprise cell centers; sim position is authoritative and render interpolation is cosmetic.

No world expansion in v0.1. At a technical population bound, queen output pauses with an explicit explanation. Do not delete older ants or silently convert population to fake counters.

## Navigation and reservations

Home routes use a multi-source BFS distance field from valid nursery/storage entry cells. Recompute after topology changes, once before next movement, for this modest grid. Outbound travel uses local exploration plus bounded A* to a discovered reachable source/frontier; deterministic neighbor order N,E,S,W breaks ties.

Budget: at most 16 new A* requests/tick, at most 4,096 expanded cells/request. Deferred actors wait/explore locally; they never teleport. A path search that exhausts the budget is pending or retryable, not proof the target is unreachable. Permanently unreachable candidates are retried only after cooldown/topology revision.

Reservations bind one entity to a quantity/target and expiry tick. Food availability subtracts reservations. Dig frontiers allow 2 workers per target cell. On death, invalidation, or timeout release reservations and retain any actual cargo. Actor search has a 10-second retry cooldown after a failed target; carried cargo takes priority over a new task.

Topology changes bump a navigation revision. Before entering the next cell, check passability even if a cached route exists. Source exhaustion invalidates its reservation and sets a 5-second local avoidance memory. Ants find returning routes using the home field; trail following is a discovery bias, never the sole means of returning home.

## Task choice

Tasks: Forage, Excavate, Nurse, Clean, Idle. Normalize stimuli to [0,1]: food shortage relative to target stocks, missing nursery space relative to target, uncared brood fraction, and removable corpse pressure. Task needs cannot go negative or divide by zero.

Each worker has deterministic initial per-task thresholds in [0.25,0.75]. Calculate response `s*s / (s*s + theta*theta)` using bounded fixed-point intermediates. Scale by focus and current-task persistence. Draw once from the weighted eligible tasks plus Idle weight 0.1. Do not independently roll jobs in a fixed list: that biases earlier entries.

Ineligible tasks have zero weight: no frontier, no food target, no brood, or no mature corpse. Keep a task for at least 5 seconds unless invalid or interrupted by starvation safety. Cargo must be delivered or dropped explicitly before reassignment. Colony focus multiplies one task weight by 1.5, others by 1.0: Growth=Nurse, Expansion=Excavate, Foraging=Forage, Balanced=all 1.0. Essential work is never zeroed.

Stimuli can use colony aggregates as an intentional abstraction. Worker choices remain distributed; no hidden quota manager assigns exact headcounts. A starvation safety override makes an eligible idle/non-carrying worker forage when usable stores are below 10 seconds of demand.

## Food accounting

Two foods: carbohydrates and protein, expressed as milli-units. Locations are source inventory, reserved-but-not-picked source inventory, worker cargo, dropped cargo, and colony storage. Reservations are claims, never a second inventory.

Pickup moves available source quantity into cargo up to capacity and free storage commitment; delivery moves cargo to stores up to free capacity. Carry leftover cargo if stores filled meanwhile. Source refills add documented external supply only up to its capacity. Source->cargo->store transfers preserve total mass; metabolism and discarded decomposed cargo are recorded sinks. Reject negative quantities and double delivery.

Nutrition distribution within the reachable nursery is abstracted: consumption draws from stores, not mouth-to-mouth agents. Nurses provide care that speeds development. Forage and nurse roles therefore matter without a deadlock when the last nurse dies. Each brood consumes its due food independently in stable-ID order; missing nutrition stalls that brood's development and accrues starvation.

## Foraging and trail field

Scouts explore reachable surface cells with heading persistence. Known source targets are local memory; once a worker finds food it can return using home navigation. Successful returning workers deposit a trail; outbound ants bias choices toward stronger neighboring values plus exploration noise.

One uint16 trail channel. Every 4 ticks apply evaporation with fixed-point retained fraction, then double-buffered four-neighbor diffusion with reflecting boundaries (solid/out-of-bounds neighbors contribute the center value). Saturate after deposit, never wrap. Parameter validator caps diffusion weight per neighbor at 0.25 so coefficients remain nonnegative. Start with weight 0.05 per neighbor and 60-second half-life. Convert half-life to one integer retention coefficient at load and store the effective coefficient.

No nest/food omniscience via pheromones; no smart deletion of failed trails. Stale trails decay, while target cooldowns prevent permanent fixation. Exact real-ant deposition ratios are not a required v0.1 claim.

## Excavation

Queen/nursery anchor and colony space demand determine whether excavation work is useful. Candidate cells must be diggable and adjacent to connected nest air. Score candidates by continuing an existing segment, staying near the nursery for chamber growth, and short distance to a spoil outlet. Seeded tie-breaking prevents perfect symmetry. Limit active candidate cells to 8; this is a performance bound, not an upgrade unlock.

Each cell has remaining dig work (soil 10, clay 25 units). Base worker delivers 2 work units/sec. On final hit, clear cell, bump topology/chunk revisions, and put one spoil unit in the final digger's cargo. It must deliver to surface before digging again. Other diggers release that cell and retarget. A spoil deposit changes a visual mound counter, not navigable terrain in v0.1.

Each newly connected excavated cell contributes to nursery capacity: `max(12, floor(reachable_nest_air / 4))`. Initial connected nest area is at least 64 cells (capacity >=16). Capacity limits all live brood together, not adult workers. If capacity drops in a debug edit, existing brood survive but laying pauses.

Full structural stability/collapse is out of scope. Do not implement the archive's anchored-solid flood fill as a physical support solver: connected soil can still be mechanically unsupported, and chunk-only analysis can miss remote supports.

## Brood, care, queen, and death

Queen lays one egg per interval if fed, brood capacity available, and live entity safety bounds allow it. A missed laying interval does not bank unlimited future eggs. Birth events count workers only on actual eclosion, never at egg placement. Initial six workers do not increment lifetime workers-born statistics.

Stages advance while fed; egg and pupa have no food upkeep and can still advance after queen death; larvae require both foods. A nursing visit grants 5 seconds of care to one brood; fresh care permits full development rate, absent care permits 0.5x. Nurses serve the brood with least remaining care, tie-break by ID. Care never stacks beyond 5 seconds. A visit takes 1 second next to nursery anchor.

Workers receive a lifespan sampled uniformly from 1,200 to 2,400 sim seconds, with initial workers assigned staggered starting ages from 0 to 120 seconds. This is a simple gameplay distribution, not a biological mortality claim. Winged queens have no age death during v0.1 but require adult nutrition. Queen has starvation death only.

On death, remove living role and convert to a corpse plus dropped cargo at the same position. Maintain stable identity for references or emit a documented replacement ID event consistently. Corpse becomes cleanable after 30 seconds; cleaners carry it to surface midden. It decomposes after 300 seconds whether carried or not, releasing its reservation safely. No infection system. Dropped food decays after 120 seconds with an explicit sink counter and is eligible for recovery before then.

Queen death latches Decline. Extinction is recomputed after death/maturation/spawns. Disabling care does not instantly erase brood; starvation grace periods are in ECONOMY.

## Bounds and diagnostics

Initial hard bounds: 5,000 workers, 5,000 brood, 10 winged queens/winged brood combined, 20,000 total entities including corpses/cargo. When capacity is reached, refuse spawning/laying and expose a diagnostic; retain existing entities and allow cleanup. Source count, path queue, and event counts are bounded too.

Track tick time, each system time, path requests/expansions, stuck-worker seconds, delivered food, resource sinks, births/deaths, and population. Debug invariant failures include seed/tick/system for reproduction. Runtime should not generate logs every tick by default.


## Source choice follows colony need (T013)

A forager picks between the two sources by the larger **shortfall** of that source's nutrient
against the same 50%-of-current-capacity target the foraging stimulus uses, counting food already
picked up and on its way home. Trail strength only breaks a tie.

A reservation is capped by the room actually left in the destination store: capacity minus the
stored amount, minus food already carried toward it, minus what is already reserved at the source.
Without that, several foragers each reserve a full load for a nutrient with room for one, and the
losers hold undeliverable cargo in `WaitingForStorage` indefinitely while the colony starves for
the other nutrient. Both rules were added after a measured colony death; see the
[balance report](../planning/BALANCE_REPORT.md).

A path and its cursor are cleared together. Clearing a path while leaving `next_cell` past its end
produces a movement state that snapshot validation rejects.


## Spoil becomes terrain (M5)

A worker that finishes a cell carries the grain to the surface outlet and tips it onto the mound,
which is real terrain rather than a counter. Grains settle on the lowest nearby pile, scoring
`height * 3 + radius`, so the apron grows outward as a cone instead of a tower. The entrance column
and its two shoulders are never used, so the nest cannot bury itself, and piles are capped at five
cells: an uncapped version grew eleven-cell walls either side of the entrance that every forager
had to climb. A grain is never placed on a cell occupied by an ant, corpse, brood item or dropped
cargo.

Because this turns sky into soil, it is the first thing in the simulation that makes a cell
*impassable*. Cached paths crossing that cell are invalidated by the navigation revision, so a
saved path may legitimately cross solid ground; snapshot validation therefore only requires paths
still marked current to be walkable.

## Frontier claims are counted once per tick (M5)

Each excavator used to rescan every worker for every frontier to see how many were already
committed, which made the tick cost quadratic in population and timed the sixty-minute soak out in
CI. Claims are now tallied once per tick and adjusted as workers take and give up targets — on a
new target, on finishing a cell, and on switching task. Missing any of those releases leaves
phantom claims that push excavators off frontiers and measurably slows the colony.
